## MCP: контекст платформы 1С (1C:Enterprise)

В этом проекте доступен MCP-сервер **`bsl-context`** — поиск и навигация по
документации API платформы 1С:Предприятие. Сервер читает бинарные файлы
справки (`shcntx_ru.hbk`) или JSON и отдаёт точные имена методов, свойств,
типов и конструкторов. Работают русские и английские имена (`ТаблицаЗначений`
= `ValueTable`), а также запросы вида `Тип.Метод`.

### Инструменты

| Инструмент | Описание | Параметры |
|------------|----------|-----------|
| `search` | Поиск по API платформы. keyword — по именам, semantic — по смыслу, hybrid — оба (лучшее качество). При пустом результате — подсказки «Возможно, вы имели в виду» | `query`, `mode?`, `type_filter?`, `limit?` |
| `info` | Детальная информация об элементе по точному имени | `name`, `type_filter?` |
| `get_member` | Метод/свойство конкретного типа | `type_name`, `member_name` |
| `get_members` | Список методов и свойств типа (пагинация) | `type_name`, `limit?`, `offset?` |
| `get_constructors` | Сигнатуры конструкторов типа | `type_name` |
| `get_platform_info` | Активная версия платформы и список доступных | — |
| `health` | Статус сервера и готовность режимов поиска | — |
| `get_coding_guideline` | Рекомендации по стилю кода BSL | — |
| `get_strict_typing_info` | Документация по строгой типизации BSL | `topic` (или `'topics'`) |
| `search_strict_typing` | Текстовый поиск по строгой типизации с контекстом | `query` |

### Правила использования

1. Начинайте с `search`, используя конкретные термины 1С (русские или
   английские): `НайтиПоСсылкам`, `ValueTable`, `ТаблицаЗначений.Добавить`.
2. Точные имена из результатов `search` подставляйте в последующие вызовы
   **как есть**. Шаблонные типы справочников/документов задаются полностью:
   `СправочникОбъект.<Имя справочника>` (включая угловые скобки).
3. Для полной документации по найденному элементу — `info` с точным именем.
4. Для обзора методов/свойств типа сначала `get_members`, затем `get_member`;
   `get_constructors` — для сигнатур создания объектов.
5. `search`-режимы: `keyword` — точные имена, `semantic`/`hybrid` — запросы на
   естественном языке («как добавить строку в таблицу значений»).
6. Строгая типизация: `get_strict_typing_info` (сначала `topic='topics'`);
   стиль кода — `get_coding_guideline`.
7. Перед первым semantic/hybrid-запросом (или при сомнениях) вызывайте
   `health`: семантика инициализируется лениво (модели + индекс), первый запрос
   может занять минуты. Если семантика недоступна, `search` сам вернётся к
   keyword с пометкой — не придумывайте имена API, которых нет в ответах.
8. Текущую версию платформы смотрите через `get_platform_info`.
