## Шаги

### Шаг 1 — критический FAIL (#8/#9)
- Добавить `import re` в `mcp_bsl_context/server.py`.
- Регрессионный тест на уровне сервера (JSON-источник в tmp_path, tool-функция `search`): запрос без совпадений (`«абвгдеёжзиклмнопрст»`, mode=keyword) возвращает чистый вывод без «Внутренняя ошибка»; опечатка `«НайтиПоСсыцке»` даёт подсказку.
- Прогон `pytest`, коммит.

### Шаг 2 — MINOR (#24): словоформы в `search_strict_typing` ✅ (commit 6211986)
- Токенизация запроса по словам; тема засчитывается при совпадении **хотя бы одного** слова (векторные веса), фолбэк — «любое слово» с приоритетом по числу совпавших; превью центрируется на первом совпавшем токене.
- Тесты: «Массив конструктор» → тема `arrays`; «ТаблицаЗначений» без регрессий.
- Прогон `pytest`, коммит.

### Шаг 3 — MINOR (#7): hybrid-ранжирование ✅ (commit 0e68ede)
- Устранён двойной реранк: hybrid берёт от semantic сырую ANN-выборку (`rerank=False`) и реранкает объединённый пул один раз.
- Keyword-движок: `word_weight()` (веса по длине слова), `word_matches()` (substring или стем словоформы), матчинг по имени типа-владельца.
- RRF `KEYWORD_WEIGHT` — константа, измеренный оптимум ~1.0 (вес > 1.2 ухудшает результат; первоначальный буст 3.0 затапливал пул реранкера шумом).
- Embed-текст (`document_builder.py`): параметры методов с типами («Значение (Произвольный)»).
- Сменён `_FINGERPRINT_NAMESPACE` в `semantic_engine.py`; пересборка индекса прошла (591 документ).
- Проверка на реальном HBK: «как найти строку в ТЗ по условию» → «ТаблицаЗначений.НайтиСтроки» в топ-3, «Вставить» вне топ-10.
- Прогон `pytest`, коммит.
