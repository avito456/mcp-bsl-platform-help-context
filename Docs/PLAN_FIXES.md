# План: исправление ошибок по результатам тестирования MCP `bsl-context-1c`

> Дата: 2026-09-20
> Источник ошибок: `Docs/bsl-context-1c_тестирование.md` (тесты от 2026-09-20, версия платформы 8.5.1)
> Файл справки **HBK: `/opt/1cv8/x86_64`** (Linux-путь хоста тестирования; на macOS раскладка `/opt/1cv8/<версия>/`, в `config.yml` — `platform.path: /opt/1cv8`, версии ищутся рекурсивно).

## Диагноз (подтверждён воспроизведением)

| # теста | Ошибка | Root cause | Статус |
|---------|--------|-----------|--------|
| #8, #9 (критический FAIL) | keyword-поиск без совпадений → «Внутренняя ошибка» | `NameError: name 're' is not defined` в `server.py:383` — модуль не импортировал `re`; `re.search` вызывается только в ветке «нет результата» (блок «did you mean») | Подтверждён traceback'ом сервера |
| #24 (MINOR) | `search_strict_typing` «Массив конструктор» → 0 | `docs_service.py:75` ищет всю фразу одной подстрокой (`content.find(query)`); многословные запросы не встречаются подряд | Подтверждён воспроизведением |
| #7 (MINOR) | hybrid: топ-1 «Вставить» вместо «НайтиСтроки» | RRF-фьюжн + cross-encoder реранкер: семантическая близость «Вставить» к «добавить строку» выше; keyword-попадания не получают преимущества | Подтверждён историей проекта (bebc80e) |

## Шаги

### Шаг 1 — критический FAIL (#8/#9)
- Добавить `import re` в `mcp_bsl_context/server.py`.
- Регрессионный тест на уровне сервера (JSON-источник в tmp_path, tool-функция `search`): запрос без совпадений (`«абвгдеёжзиклмнопрст»`, mode=keyword) возвращает чистый вывод без «Внутренняя ошибка»; опечатка `«НайтиПоСсыцке»` даёт подсказку.
- Прогон `pytest`, коммит.

### Шаг 2 — MINOR (#24): словоформы в `search_strict_typing`
- Токенизация запроса по словам; тема засчитывается при совпадении **всех** слов, фолбэк — «хотя бы одно» с приоритетом по числу совпавших; превью центрируется на первом совпавшем токене.
- Тесты: «Массив конструктор» → тема `arrays`; «ТаблицаЗначений» без регрессий.
- Прогон `pytest`, коммит.

### Шаг 3 — MINOR (#7): hybrid-ранжирование
- Буст keyword-списка в RRF (`hybrid_engine.py::_rrf_merge`, вес keyword > 1).
- Улучшить embed-текст (`document_builder.py`): контекст типа-владельца + сигнатура в build_from_method/property.
- Сменить `_FINGERPRINT_NAMESPACE` в `semantic_engine.py:25` — иначе старый индекс не пересоберётся после изменения формата текста.
- Проверка на реальном HBK: «как найти строку в ТЗ по условию» → «НайтиСтроки» в топ-3.
- Прогон `pytest`, коммит.

### Шаг 4 — финализация
- Полный прогон `pytest`.
- Обновить `Docs/bsl-context-1c_тестирование.md` (статусы статей) и `Docs/CHANGELOG.md`.
- Коммит.
