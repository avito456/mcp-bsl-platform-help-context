## Шаги

### Шаг 1 — D1: супплемент глобальных методов
- Бандленный `mcp_bsl_context/docinfo/global_methods_supplement.json`
  `[{name_ru, name_en, description, signatures?}]` — только подтверждённые данные,
  сигнатуры не выдумывать (при сомнении — имя + описание).
- Мерж в `PlatformContextStorage` после чтения HBK, **дедуп по RU/EN-имени**
  (не перезаписывает реальные данные HBK).
- Конфиг-флаг `platform.use_supplements: true`.
- Тесты: `Выполнить`/`Execute` доступны через info/search; существующие методы не дублируются.

### Шаг 2 — D2: релевантность keyword
- `word_matches`: точное слово → camelCase-сегменты alias (`word == seg` или
  `seg.startswith(word)` при len≥3) → инфлекция стеммером «срезание хвостовой
  гласной/й» (`строку`→`строк` ⊂ `Строки`, но `полет` не сворачивается в `поле`)
  → свободная подстрока **только на границе сегмента** (не в середине слова).
- Coverage-фильтр в `SimpleSearchEngine.search`: вес совпавших слов ≥ порога от
  общего веса запроса; ниже порога результат отсекается → пусто → «did you mean».
- Регресс-тесты: `строку→НайтиСтроки`, `ПоСс→НайтиПоСсылке`, ё; новые: мусорный
  токен → «Nothing found»+подсказка; `полет` не матчит `ПолеКомпоновкиДанных`.
- Итог реализации (коммит Шаг 2): сегмент-чувствительный `word_matches`
  (точная подстрока/сегмент → инфлекция через `_russian_stem` → свободная
  подстрока с хвостовым срезом). Coverage-фильтр **отклонён**: порог по весу
  запроса математически несовместим с существующим тестом ранжирования фразы
  «как найти строку в таблице значений» (там покрытие 10/27, а мусор давал
  9/13 — оба условия одновременно невыполнимы, см. анализ в ходе шага).
  Шум обрабатывается так: чистый мусор → пусто + did-you-mean; реальное имя +
  мусор → реальное имя первым (подтверждено на реальном HBK).

### Шаг 3 — D3: устранить crash-источник (MPS)
- `config.yml`/`config.example.yml`: `embeddings.device: cpu`, `reranker.device: cpu`.
- `LocalEmbedder`/`LocalReranker`: передавать `device` в
  `SentenceTransformer(..., device=...)`, `CrossEncoder(..., device=...)`; валидация
  значения. CPU: задержка для этих моделей ~0,1–0,4 с (замерено), MPS способен
  убить процесс (abort() не перехватывается).
- Тесты: конструкторы принимают device; default cpu.
- Верификация: stdio-сессия с реальным HBK — несколько semantic/hybrid
  (в т.ч. параллельных) без SIGABRT.

### Шаг 4 — D4: дедупликация версий
- В сборке `available_versions` — дедуп по значению версии (порядок сохраняется);
  активная помечается однажды; опционально полный билд активной в заголовке.
- Тест: `get_platform_info` без дублей.

### Шаг 5 — D5: унификация языка вывода
- `formatter.py`: `## Методы` / `## Свойства` / `## Конструкторы` / `**Методы (N):**`;
  обновить `tests/test_formatter.py` (строки 60–61, 104, 117–118).
