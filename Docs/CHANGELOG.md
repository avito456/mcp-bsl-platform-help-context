# Changelog

Все заметные изменения проекта документируются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Проект ещё не выпускает semver-версии: изменения группируются по дате.

## [Unreleased]

### Исправлено

- **Асинхронный прогрев семантики (`warmup`).** Модели теперь загружаются в
  фоновом потоке на старте — запуск сервера и MCP-хендшейк не блокируются.
  Первый semantic/hybrid-запрос больше не повисает на загрузке моделей и не
  упирается в таймаут MCP-клиента (opencode: «Request timed out» / “connection
  closed”): ожидание готовности ограничено ~15 с
  (`SEMANTIC_READY_WAIT_TIMEOUT`), при недошедшем прогреве запрос возвращает
  keyword-результаты с пометкой о неготовности семантики. `health` показывает
  промежуточный статус «initializing…». `reindex` остаётся синхронным.

### Добавлено

- **Интерактивная установка (`install`).** На терминале голый
  `uv run mcp-bsl-context install` запускает мастер: определяет ОС и
  предлагает типовой каталог 1С, при нескольких версиях даёт выбрать
  (`Enter` — последняя, свободный ввод, `auto` — не фиксировать) и
  подтверждает запись. Версия пишется в `config.yml` как
  `platform.version`; уточняются только нерешённые автоматически значения.
  Новые флаги: `--platform-version`, `--yes`/`-y`, `--non-interactive`.
  Не-tty (CI/скрипты) — прежнее неинтерактивное поведение.
- **ОС-зависимый поиск платформы в мастере `install`.** Авто-резолв каталога
  1С идёт по каталогам установки текущей ОС (macOS: `~/Applications/1cv8`,
  `/Applications/1cv8`, `/opt/1cv8`; Linux: `/opt/1cv8[/x86_64]`; Windows:
  `C:/Program Files/1cv8`), а не по жёсткому списку. Найденные версии
  выводятся нумерованным списком — выбирать можно по номеру. Если
  установленных платформ нет, мастер спрашивает каталог с файлом справки
  `*.hbk` и проверяет его наличие (вводится до успешного каталога).
- **Авто-поиск платформы при запуске сервера.** Если `platform.path` не задан
  для `hbk`-источника (ни в `config.yml`, ни через `--platform-path`/
  `MCP_BSL_PLATFORM_PATH`), сервер при старте ищет платформу 1С по
  каталогам установки текущей ОС (и встроенный HBK в репозитории сервера);
  запуск `mcp-bsl-context --warmup` без `-c` больше не падает с ошибкой
  «platform.path is required», если платформа установлена.
- **AI-readiness (этап A).** Все сущности API (методы, свойства, типы) получили
  английские имена-алиасы (`name_en`): `ValueTable` → `ТаблицаЗначений`,
  `FindByRef` → `НайтиПоСсылкам`. Поиск и `find_*` матчат по русским и
  английским именам; дедупликация результатов по русскому имени.
- **Поиск «Тип.Метод».** Запросы вида `ТаблицаЗначений.Добавить`,
  `ValueTable.Add`, `СправочникОбъект::ПолучитьСсылку` разбираются на тип и
  член; точное совпадение возвращается первым результатом.
- **Owner-тип в выдаче.** Результаты поиска и `get_member` показывают
  тип-владелец (`ТаблицаЗначений.Добавить`).
- **Автодетект типа в `info`.** Параметр `type_filter` стал необязательным:
  тип элемента определяется автоматически (метод → свойство → тип); при
  неоднозначности возвращаются варианты с подсказкой.
- **Инструмент `health`.** Статус сервера: версия платформы, источник данных,
  статистика контекста и готовность semantic/hybrid.
- **Прогрев семантики.** Флаг `--warmup` / `MCP_BSL_INDEX_WARMUP` /
  `index.warmup: true` загружает модели и готовит индекс при старте без
  пересборки.
- **Did-you-mean.** При пустом результате keyword-поиска возвращаются
  ближайшие по расстоянию редактирования имена (`engine.suggest`).
- **Двуязычные описания инструментов** (RU + EN) и EN-блок в
  SERVER_INSTRUCTIONS.
- **Интеграционные тесты на реальном HBK** и grep-guard, который запрещает
  несуществующие имена API в документации.

### Исправлено

- **Keyword-поиск без совпадений больше не падает.** В блоке did-you-mean
  использовалась переменная `re` без импорта — бессмысленный запрос в режиме
  `keyword` возвращал «Внутренняя ошибка» вместо пустого результата и подсказки.
  Добавлен `import re`; регрессионный тест на реальном серверном туле.
- **`search_strict_typing` ищет по словам.** Раньше запрос матчился одной
  подстрокой, и «Массив конструктор» давал 0 совпадений. Теперь запрос
  разбивается на токены, тема попадает в результат при совпадении любого из
  них; ранжирование по числу совпавших слов и позиции первого совпадения;
  превью центрируется на совпадении. «Массив конструктор» → 13 тем, `arrays`
  первая.
- **Hybrid-ранжирование («как найти строку в ТЗ по условию»).** Semantic-движок
  реранкал свою ANN-выборку до слияния с keyword (двойной реранк) и ставил на
  1-ю позицию «Вставить». Hybrid теперь берёт от semantic сырую ANN-выборку
  (`rerank=False`) и реранкает объединённый пул один раз; keyword-движок
  матчит русские словоформы по стему («строку»→«стро») и учитывает имя
  типа-владельца. Итог: `ТаблицаЗначений.НайтиСтроки` — топ-3, «Вставить» вне
  топ-10.
- Убраны выдуманные примеры API (`НайтиПоСсылке`) из инструкций, docstrings и
  README: такие имена не существуют в данных и ломали копируемые запросы.
- Шаблонные имена больше не экранируются бэкслешами: `СправочникОбъект.<Имя
  справочника>` копируется в `info`/`get_member` как есть.
- Авто-fallback: если semantic/hybrid недоступны (модели/индекс),
  `search` возвращает результаты keyword с явной пометкой вместо ошибки.

### Технические детали

- Embed-текст семантического индекса дополнен EN-алиасами; fingerprint индекса
  изменён — пересборка произошла автоматически при первом semantic/hybrid
  запросе (или по `--reindex`).
- Методы в embed-тексте `DocumentBuilder` теперь несут типы параметров
  («Параметры: Значение (Произвольный), Колонки (Строка)»); fingerprint изменён
  (591 документ, пересборка уже пройдена).
- Keyword-движок: весовой подсчёт совпадений (`word_weight`: короткие
  функциональные слова ≈ 0), матчинг по стему словоформ и по имени
  типа-владельца. RRF вес keyword-списка (`KEYWORD_WEIGHT`) — измеримая
  константа ~1.0 (значения > 1.2 ухудшают ранжирование).
