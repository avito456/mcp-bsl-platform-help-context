## Задачи

### 1. Инструкции модели через FastMCP `instructions=` (приоритет: высокий)
- `mcp_bsl_context/server.py`: `FastMCP("mcp-bsl-context")` не передаёт `instructions=` (параметр поддерживается в FastMCP 4).
- Вынести текст из README «Инструкции для AI-ассистентов» в код как `instructions=`.
- MCP-клиенты (Claude Desktop, Cursor и др.) автоматически встраивают их в системный промпт — модель сразу знает правила: когда использовать `search`, когда `info`, что имена из таблиц результатов можно использовать как есть, semantic/hybrid — для естественно-языковых запросов.

### 2. Версия платформы (приоритет: высокий)
Варианты (нужно выбрать):
- **(a)** Положить `shcntx_ru.hbk` в каталог с номером версии (например `8.3.25.XXXX/`). `VersionDiscovery` распознает версию автоматически (`config.yml` → `platform.path`).
- **(b)** Автодетект версии по содержимому HBK (парсить номер из TOC/страниц) — работает при любой раскладке.

Результат: модель сможет сообщать, к какой версии платформы относится документация.

### 3. Полировка description/docstrings инструментов (приоритет: средний)
- `search`: явно описать, что keyword отдаёт точные имена, которые затем можно подставлять в `info`/`get_member(s)`; имена могут содержать шаблонную часть (`СправочникОбъект.<Имя справочника>`) — подставлять их целиком.
- `info`/`get_member`/`get_members`: при «Type not found» возвращать подсказку («возможно, тип шаблонный — найдите точное имя через `search type=type`»), чтобы модель не зацикливалась.

### 4. README: раздел про готовность semantic-поиска (приоритет: средний)
- Зафиксировать, что первый семантический вызов после установки медленный (скачивание моделей + сборка индекса) — это разовый шаг.
- Добавить команды: `uv sync --extra local`, индексация через `--reindex`, пути `./data/qdrant` и `./data/models`.

### 5. (Опц.) E2E-смок-тест semantic/hybrid (приоритет: низкий)
- Тест-проверка факта наличия коллекции в `data/qdrant` без тяжёлого инференса в CI.
